# v0.7 费用申请与核销验收

## 交付与决策
新增可选事前申请：员工创建、主管批准/驳回、员工结束；预算视图区分报销在途与申请未核销预留。报销可关联同员工、部门、月份和类型的已批准申请，累计不得超批准额度；申请额度不支持中途修改，计划变更可结束后另行申请。

部门预算继续采用软预警，审批窗口展示预计余额；申请批准额度采用硬限制。这是两层不同政策，不把批准费用当成实际支出。

## 验证证据
- 25 项业务测试通过，覆盖状态、权限、分级额度、按分计算、预算不重复占用、结束释放、非法关联与备份兼容。
- 共 22 项真实 Chromium 场景通过（整套 21 项及新增异常存储场景，补充修正后重跑相关 5 项），涵盖原有 OCR、审批、付款与新申请闭环。
- 新完整流程：1000 元申请批准 → 关联 600 元报销 → 审核付款 → 余额 400 预留 → 结束释放；付款信息和申请关联刷新后保留。
- 旧备份恢复保留当前申请，新备份包含申请；移动端无整页溢出。
- 构建与单文件导出成功；生产产物的 `/-/` 路径创建和批准成功，项目案例 PDF 已更新。

## 联调修正
申请保存逻辑初次调整时未正确使用新集合，浏览器测试发现记录未显示；修正为存储成功后更新内存，并重跑相关场景及全部测试。

## 限制
仍为浏览器本地演示，无真实身份、跨设备同步或并发预算事务。未支持跨月核销、申请变更、多级组织审批、验真或银行支付。新功能不等于真实用户或业务效果验证。

补充保护：申请存储损坏时不导出假完整备份，不用缺少申请的旧备份覆盖未知数据；恢复包含申请的有效备份时仍需用户明确确认替换。
