# 如何打开轻报

## 方式一：单文件演示（无需开发工具）
下载 `qingbao-demo.html`，保留 `.html` 后缀，用 Chrome 打开。网页已经包含所有样式和脚本，无需登录、联网或安装 Node.js。请使用虚构资料。

员工、主管、财务可在右上角切换。报销、规则、预算保存在浏览器中；换浏览器或清理数据可能丢失，可在“数据管理”导出备份。文件复制到别处后，浏览器可能将其视为另一个存储空间。

如果系统将文件保存为 `.txt`，将后缀改回 `.html`。企业管理的浏览器可能禁止打开本地文件，可采用下方开发服务或静态托管方式。

## 方式二：源码运行
安装 Node.js 22.12 或更高版本，将项目解压，在含 package.json 的目录执行：

```sh
npm ci
npm run dev
```

按终端输出访问本机服务。云环境中的 localhost 与用户电脑不是同一台设备，不能把云端 localhost 当成公网网址。

## 方式三：GitHub Pages 发布公开演示
此仓库已添加 `.github/workflows/pages.yml`。它会安装依赖、运行业务测试、构建，然后部署静态文件。**配置已准备，尚未执行公开部署。**

1. 将完整项目提交到你自己的 GitHub 仓库。现有项目为 `Jameyan42/-`，请确保新增文件也提交，而不仅是原 README。
2. 在仓库 Settings → Pages 中，选择 Source 为 GitHub Actions。
3. 在 Actions 中找到 “Publish Qingbao to GitHub Pages”，点击 Run workflow，选择 main 并运行；后续 main 更新也会触发。
4. 等待 build、deploy 成功，在部署结果或 Settings → Pages 中打开平台生成的网站地址。以实际部署输出为准。

若仓库为私有仓库，Pages 可用性与访问范围取决于 GitHub 套餐和组织设置。公开演示只应含虚构样例。网站数据仍留在每位访问者自己的浏览器，不是多人协作系统。GitHub 站点公开后也不要写入真实财务信息。

## 验证与重新生成演示

```sh
npm test
npm run build
npm run export:demo
```

可选的真实浏览器流程测试：

```sh
npx playwright install chromium
npm run test:e2e
```

在当前云环境已安装 Chromium，可执行：

```sh
QINGBAO_BROWSER_PATH=/usr/bin/chromium npm run test:e2e
```

重新生成的单文件位于 `deliverables/轻报演示.html`。发布前请确认从首页到报销付款的完整闭环，并使用“重置演示数据”恢复样例。
