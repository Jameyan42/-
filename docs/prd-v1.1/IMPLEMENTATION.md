# 员工费用报销单 v1.1 实施边界

基线153c978；原PRD保持原字节。沿用原业务入口、PG和四角色，不修改冻结纯规则。

- 新录单使用modelVersion=2和五主类型，旧单继续原模型/状态编码；不把混合旧单静默重分类。PRD状态名与原状态名含义相同，沿用数据库编码并显示中文。
- 新草稿可空业务字段，但已输入金额/日期仍必须合法；提交时统一返回字段路径，保存和提交校验分离。
- 费用承担部门默认本人部门，本期普通员工不可改。未另行授权时不启用跨部门承担。
- 原主管→财务状态就是有效待办，不重复创建第二套审批表；预览只读，提交重验，固化路径/版本。无主管、自批或无其他有效财务时阻止新单提交。
- 收款账户采用本人维护、加密原值、脱敏展示、待验证、失效状态；验证制度默认未配置。管理员明确启用“线下财务核对”后，非本人财务凭真实核对依据确认。仅记录人工验证，不宣称银行实名认证。测试只配置虚构制度。已提交冻结账户快照，不支持直接改账号，需退回重提；历史单不强制补造账户。
- 不自动启用无票、招待人均标准、预算预占、AI、第三方收款、特殊审批。现行发票必填和现有政策继续；费用分类未知返回人工核查而不是模拟R005。
- 当前支持原四种发票类型；客运电子票可录入已有支持的数电票。其他票种及企业差异化免抬头/无票制度待明确，不使用假税号通过。
- 撤销仅在企业明确启用且主管尚未处理时允许，原件/历史保留；发票释放仍按提交时公司制度，不改变旧释放政策。
- 银行账户加密密钥独立于SESSION_SECRET，以环境变量提供，不入库、不入日志；缺密钥不允许录入完整账号，不回退明文。备份恢复须另外安全保管密钥。
- 当前公网入口仍未交付；本地/隔离数据库验证不等于正式企业使用验收。

- 日期仅硬校验日历有效、退房晚于入住及出差开始/结束顺序；不擅自规定购票费用发生日必须在行程内，避免拦截提前购票。额外期间制度由企业确认。
- 账户失效的待付款单：只有非本人财务确认尚未实际线下付款后可退回，保留原快照和历史，重提需完整重新审批；已付款不允许退回改账号。
