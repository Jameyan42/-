# 差旅行程与费用明细设计

## v0.15：差旅行程、费用明细与示例标准

本轮连通三个功能：出差申请补充出发地、目的地、出发/返回日期、城市档和示例职级档；差旅报销可启用1～20行费用明细（城际交通、住宿、餐补、市内交通、其他），自动合计；按固定版本示例标准检查住宿和餐补，超标说明必填后交由人审核。新增只读“差旅标准”页解释金额及口径。

员工 → 费用申请 → 新建，勾选“这是出差行程申请”；按原申请审批路径批准并预留预算。员工新建报销，选择本月已批准申请时自动载入行程并启用差旅明细；报销的行程和批准申请必须一致，关联金额仍受剩余额度硬限制。未关联申请也可手动启用差旅明细。旧普通报销不强制补填。

示例演示：林晓申请杭州至上海10月21～23日、2000元；赵航批准。关联报销填住宿1000元/2晚、餐补300元/3天、城际交通200元，自动合计1500元；主管→财务审核→模拟付款，申请剩余500元，付款后可结束申请释放未用余额。另填住宿1100元/2晚，显示超过500元/晚，要求说明后提交，审核人在详情查看超标与理由。

这是自定义示例制度，不代表法定标准或真实企业政策。城市/职级档手工声明，未接HR；标准只读，版本travel-demo-2026-01。住宿按实际晚数、餐补按含首尾自然日；重复住宿/餐补日期、越界日期、合计不一致会被拒。跨月行程暂需拆分，批准申请只在报销归属月份一致时可关联；报销日期仍沿用原提交/原单日期，不按行程自动改预算月份。

超标说明不自动豁免审批或原有单笔上限、缺附件、重复号码检查。明细行金额是行合计，不支持逐票附件、多票OCR、发票验真、自动订票或真实支付。启用差旅后的草稿也需完整行程及明细；可关闭差旅模式继续普通草稿。JSON备份保留行程、明细、理由和版本，非法合计/行程拒绝导入且不覆盖原数据。

## 模型与取舍

沿用费用申请而不新增一套互不关联的出差审批：申请可选trip元数据，仍使用原组织/流程快照、预算预留和申请结束规则；报销可选travel对象（schema、trip、lines、exceptionReason、policyVersion），原amount必须等于逐行分币合计。旧单不迁移，新字段不触发数据重置。

价格标准是可解释的示例制度：重点城市普通员工500元/晚、管理人员700元/晚；其他城市350/500元/晚；餐补普通100元/天、管理150元/天。目的地不自动映射城市档，职级不从演示角色推断，由审核人核对。当前唯一标准版本的规则保持不变；未来若开放编辑须增加版本解析，不能直接替换历史标准。

住宿行起始日为入住日，数量为连续晚数；最后一晚必须早于返回日。餐补起始日为第一天，数量为连续天数，最后一天不晚于返回日。每一类别的日期区间不可重叠，跨行不能通过拆分绕过单日标准；交通和其他数量为1，金额为整行实际合计。日历运算按UTC年月日差计自然日，避免夏令时23/25小时误差。行程最多31天且同一月份。

## 异常与审批

结构、日期、合计和申请额度为硬限制；住宿/餐补超标为需说明的人工判断。提交前校验说明；规则预审在说明缺失或明细非法时提示风险，正常有说明的超标不自动阻塞财务，但详情始终保留超标信息。其他已有风险仍会阻止财务通过。付款仍是人确认的模拟登记，金额取整单明细合计。

切换类型或解除申请不自动删除已填明细；若启用差旅但费用类型不一致会提示修正。关闭差旅模式表示不保存该元数据，金额恢复可手填，原普通报销入口继续可用。此选择不代表生产环境的强制制度，不应宣称防绕过权限。

## 验证与复盘

业务测试分别验证行程、价格边界、分币合计、日期分配、超标说明、原风险不被豁免、批准行程匹配和备份兼容。浏览器按实际创建申请、批准、关联明细、审批付款走通，并覆盖草稿、异常与手机。没有真实员工或财务的可用性数据，不宣称差旅处理时长下降。

后续优先收集完整差旅路线反馈，再评估逐票附件/多票OCR及跨月归属，不把它们记为本次完成。职级与城市档的真实来源、超标授权、制度版本管理需要后端与业务规则设计。
