# 报销附件与本地留存设计

## v0.17：报销多附件与证明材料

新建/编辑报销 → 报销附件 / 证明材料，可多选上传PDF、PNG、JPG、WebP，并分别标为发票、酒店水单、行程单、付款凭证或其他材料。每单最多5个，单个1 MB、合计1.5 MB；为浏览器演示版容量限制。原文件保存在报销记录中，不上传外部服务；保存草稿、刷新、退回修改后仍保留。旧“发票OCR / 原票据名称”入口继续兼容，但该入口本身仍只记录名称；需保留原文件时使用新附件区。

报销详情向员工和审核人展示附件分类、名称、大小。图片可展开预览；所有支持文件可下载原文件，PDF下载后由浏览器/阅读器查看。审批详情不提供移除按钮；员工在可编辑状态移除已保存附件时会确认，只有再次保存报销才生效，关闭未保存表单仍有提醒。台账可索引和搜索新附件名称，再跳转报销详情查看。

“发票”类附件可满足原附件完整性检查，酒店水单/行程单等不自动替代发票；原发票号码查重仍按整单号码，附件不自动识别多票号码或金额，不代表票据验真。差旅明细仍共用整单附件，尚未逐行绑定或逐票OCR。

完整JSON备份包含附件原文件（编码保存），恢复后仍可下载；旧仅名称记录不补造文件。导入检查分类、数量、扩展名/类型、文件头、编码、大小与单据总容量，非法数据不覆盖原数据。备份仍限制5 MB；浏览器总容量不足会提示。保存报销先写成功再更新内存；备份多键恢复写入失败时尝试回退已写入键，原测试数据回退已验证，异常无法回退时明确提示。

演示：员工填写200元报销，旧OCR入口选择发票；新附件区上传虚构酒店水单PDF和行程截图PNG，分类后保存草稿。刷新再编辑提交，切主管查看两份材料，展开图片并下载PDF。导出备份并在独立测试环境恢复，原PDF字节一致。请用虚构材料，备份含原文件，应由用户自行保管。

当前为本浏览器本地存储，不跨设备同步；清理浏览器数据会丢文件。图片只支持预览，不编辑原图；PDF不内嵌预览。文件头检查不是恶意文件扫描，也不能保证票据真实。没有云文件服务、细粒度下载授权、加密存储或永久留存承诺。

## 模型与取舍

新增可选attachments数组，每个文件包含稳定ID、名称、材料类型、MIME、字节大小和data URL。采用小容量嵌入式本地存储，使现有JSON备份完整携带原文件，避免将独立文件库和单据索引分离后产生丢失引用；代价是Base64膨胀和容量较低，不作为生产大文件方案。整份报销序列化附件容量保护约220万字符，浏览器实际可用空间可能更低，失败必须保留表单让用户减少本次附件重试。

选择一批文件后先读入临时编辑副本，整批校验通过才追加；失败不丢已有文件。相同名称和内容重复上传会提示，同名不同内容可保留。关闭编辑不将临时文件写入已保存报销；读取中拦截保存。图片以数据URL只作img预览，PDF不在页面执行或内嵌，下载使用临时Blob URL并回收。

已有OCR读取流程继续独立：仅选择OCR图片不自动承诺存原图，旧单只有名称仍明确标注。用户可在新附件区另外上传发票原件或证明材料；分类是演示手工声明，财务须核对，不能作为生产防绕过机制。

## 保存与恢复

报销保存先序列化校验、写localStorage成功，再更新内存；操作日志若因容量失败，提示文件已保存而日志未写入，不将成功文件伪报失败。导入备份先完整校验并由用户确认，所有将写入键先保留旧值；中途失败移除本次已写键，再恢复旧值。此为单页面失败回退，不能抵御浏览器崩溃或多标签并发，生产应改为服务端事务与对象存储。

不因上传失败或容量不足自动清理已有文件/单据。更大容量、跨设备共享、病毒扫描、权限、过期保留与加密需要后端方案；当前不新增费用或公开服务，不改变现有网站公开范围。

## 验证与复盘

验证文件实际下载字节，而不只看名称；分别覆盖草稿刷新、审核查看、有效备份恢复、非法数据不覆盖、存储配额失败回退和手机文本转义。没有真实酒店水单或客户财务资料，不将虚构材料测试宣称合规归档或效率收益。
