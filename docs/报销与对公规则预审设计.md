# 报销与对公规则预审（v0.21）

阶段记录日期：2026-10-24（Asia/Shanghai）。用户选择暂不接入真实AI，优先以可配置规则提示审核人风险。本阶段没有模型调用、合同/票据外传或新增付费服务。

## 产品目标与职责
在人工审批前把可由结构化字段确定的疑点展示出来，说明“触发依据、关联单号、核对建议”，减少审核人逐字段找线索的负担。规则不是违规结论、发票验真、业务真实性核验或自动审批。所有业务数据仍是本浏览器虚构演示，身份选择不是真实权限系统。

规则分两层：旧报销制度保留单笔上限、票据完整性和发票号码重复三个可配置硬检查，以及既有差旅明细完整性校验；新增10条补充规则默认仅提醒。财务可在“规则配置”逐条启停、选择提醒/拦截，调整有参数规则的阈值并填写原因。采用固定规则目录，不支持任意脚本、任意嵌套条件或自动从制度文本生成规则。

提醒不阻止人工继续，不要求单独确认风险，也不把通过操作称为“已核实每项风险”。审核人可在原处理备注记录核对依据。拦截在财务审核、总账复核和付款登记通过前生效；主管仍可批准业务合理性并转交财务核对，也可退回。退回必须有原因，始终保留修正入口。合同额度、指定人、总账字段和付款确认等已有固定业务校验不能被关闭。

## 规则目录

| 类型 | 规则 | 默认与判断依据 | 边界 |
| --- | --- | --- | --- |
| 报销 | 未填写发票号码 | 提醒，号码字段为空 | 不代表没有开票 |
| 报销 | 未留存发票原文件 | 提醒，已存附件没有“发票”分类 | 原附件名称和OCR核对来源不算文件留存；水单不是发票 |
| 报销 | 疑似重复报销 | 提醒，同一申请人、部门、日期、类型和分币金额，排除本人单ID及草稿/退回/撤回 | 可能是合法多笔同额支出；新快照存在双方人员ID时还需ID一致 |
| 报销 | 日期距检查日过久 | 提醒，默认超过90天，1～365整数可配 | 按上海自然日，单据日期不是发票开具日；等于阈值不命中 |
| 对公 | 单笔大额 | 提醒，默认大于50000元，可配0.01～100万元 | 不使用报销3000元标准；等于阈值不命中 |
| 对公 | 供应商停用 | 提醒，当前档案active为false | 在途可能有存续付款义务，不自动取消 |
| 对公 | 收款快照变更 | 提醒，对比全称、代码、户名、开户行、账号 | 提示变化字段和账号；不回改原快照，必要时退回重提 |
| 对公 | 疑似重复支付 | 提醒，同合同、期望付款日期和分币金额 | 不等于已发生重复银行转账 |
| 对公 | 期望日超合同范围 | 提醒，期望日早于开始或晚于结束 | 合法尾款可在期后支付，仍需人工读付款条件 |
| 对公 | 累计占用接近总额 | 提醒，在途+已付默认达到90%，1～100整数可配 | 达到即提示，超过100%仍由不可关闭的合同额度校验阻止 |

对公缺合同/供应商上下文、未复核或版本不一致、合同累计超额也会作为固定完整性风险提示，正常存储和提交本来就有相关硬校验，不将其重复包装为本轮新增业务能力。

关联证据最多展示前三个单号，更多时说明总匹配笔数，不把全量匹配原文写入每条结果。全库匹配使用当前浏览器可读取记录，不是后台黑名单、跨企业查重或服务端财务数据。

## 检查时机与界面
报销及对公列表展示当前提醒/拦截数量，详情展示风险、依据、建议与本次完整规则参数。列表、详情渲染是只读计算，不写业务数据或结果日志。当前规则变更作用于现有单据的当前提示，包括已结束单据，但不会重写审批结论或自动发起资金动作。

报销单笔处理、批量模拟付款和对公处理在执行时重新计算，不能只依赖列表之前的结果。批量付款任一单命中拦截则整批不保存。主管允许转交财务，财务/总账/付款不可通过未修正拦截。现有指定人权限、预审、总账、付款字段和参考号判重均保留。

新报销和对公每次审批或退回，在该条流转记录追加 `precheck` 快照，包含单据ID/类型、检查时间、当时金额和单据日期、完整规则开关/模式/参数及版本、命中结果。原处理记录保留处理人、动作和备注。退出、浏览和失败尝试不生成成功处理快照；员工提交/撤回不伪造审核结果。旧历史不补造。

详情可展开“处理时预审快照”，与顶部“当前检查”分开；调整规则后旧快照仍保留原阈值。保存的是系统当时计算结果，不宣称审核人已逐项确认。时间使用上海显示，快照存储ISO时间。

## 配置、持久化与兼容
复用 `qingbao-policy`，原三个字段不变，新增可选 `precheck`：schema1、version和固定10条rules。没有新增字段的旧政策使用内置v1补充提醒；保存后版本递增。旧备份无新字段仍可恢复，备份导入同时验证新增规则与报销/对公历史快照；旧记录无需新字段。

设置写入成功后才更新内存和页面，配额失败保留表单和原规则。规则保存成功但操作日志失败时，明确提示规则已保存、日志失败，不误报业务失败。JSON备份原有多键回滚仍适用。

规则存储无法读取时保留原始值，列表提示未知，详情说明结果不完整；暂停财务/总账/付款通过及完整备份，不静默使用默认规则放行。允许退回要求补正。规则编辑及重置不能覆盖未知原值，需恢复有效备份。无需新增模型密钥、云服务或账户权限。

## 风险与后续
原型只提供本浏览器顺序操作，不保证多个标签页/多用户并发一致性、不可篡改日志或生产鉴权。规则版本可随备份恢复，不是全局单调版本。政策变更不做多级发布审批，也不绑定部门/法人/费用类型的任意规则组。部门预算仍按原软预警口径，没有扩展成对公预算或预审拦截。

下一步先通过虚构任务验证财务是否理解“提醒”和“拦截”区别，是否能从依据找到原单；再评估规则按组织/场景适用、疑点核销、对公原文件附件及统一待办。没有真实参与者前，不宣称提高审核准确率或节省多少时间。
