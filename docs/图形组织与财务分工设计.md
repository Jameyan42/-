# v0.10 图形组织与财务岗位分工

## 用户提出的场景

管理员希望像思维导图一样维护组织：CFO 下有法报中心、预算分析部、资金部、税务与风控部门的部门总，部门总下面是员工。员工报销先到所属部门总，再经财务审核、总账复核，最后进入付款工作台。本阶段围绕这个场景建设，不把 CFO 位于组织顶层等同于每笔费用必须经 CFO。

## 图形组织画布

组织页默认显示人员汇报图，也可切换部门归属图。节点与连接线表达上下级，支持点选节点、右侧资料编辑、快捷添加下级人员/子部门、缩放、适应画布、展开折叠；画布内部可横向和纵向滚动，手机上侧栏移到下方。首次打开定位到 CFO 或当前根节点。岗位名称与系统角色分开：CFO、部门总、总账会计、出纳是岗位；主管、财务、总账、付款等是当前模拟权限角色。

人员侧栏可设置岗位、所属部门、系统角色、直属上级及在岗状态；部门侧栏可设置上级部门与负责人。姓名和已有部门名称仍保持不变，保留原名称关联的历史记录。顶部管理者允许直属上级为空，拒绝自我上级、循环、失效引用和破坏在途责任的停用。未保存节点资料在切换节点或缩放前提醒，不静默丢弃。

新安装提供虚构 CFO 陆衡及四个部门示例，连同原业务示例共 21 人、8 个部门（含公司根节点）。已有组织不自动重写，管理员可点击“添加 CFO 示例组织”，只追加示例部门、人员和新岗位，保留原人员关系与已发布流程；遇名称或标识冲突停止而非覆盖。新组织扩展后，缺失预算按零补齐，部门预算保持软预警。

## 财务分工模板及版本

管理员在审批流程点击“载入部门总 → 财务 → 总账 → 付款模板”，先进入草稿，填写原因并校验发布才影响后续提交。模板两条业务分支默认均为申请人部门负责人，仍可自行调整条件或追加指定 CFO 等业务节点。报销尾部依次配置财务审核人、总账复核人和独立付款负责人；三者角色和人员必须有效且相互独立。

未发布模板前保留原流程，包括新安装示例；不静默改变企业配置。费用申请仍只走业务审批、批准后预留预算，不新增总账和付款节点。报销在提交/重提时固化新 schema 2 快照：业务节点 → 财务 → 总账，加上独立付款责任人；schema 1 和没有快照的旧单据保持原逻辑，不自动补上总账。

标准演示路径：叶禾（员工，法报中心）提交 200 元 → 沈岚（部门总） → 周宁（财务） → 高璇（总账） → 杜川（付款）。CFO 陆衡无需审批每笔报销。报销超过单笔规则上限仍受原风险控制，建议用 200 元虚构单据演示正常闭环。

## 总账复核

新增“待总账复核”状态与总账角色待办。总账通过前必须填写科目、核算归属（各 1～100 字）；已有未解决预审风险不能通过，退回需要说明原因。保存科目、归属、复核人标识与 ISO 时间，详情可回看。复核通过后进入“待付款”，不是直接已付款。这里只记录复核信息，不生成会计凭证、不连接总账系统、不宣称自动记账。

## 付款工作台

按待付款/已付款/全部筛选，支持事项、单号、申请人、部门和付款参考号搜索，显示单据、金额、总账复核和模拟付款结果。审批未完成的单据不会提前进入工作台；新流程只有快照中的付款人员可以办理，财务和总账不能替代；管理员可查看但不能代付款。旧单据仍由原财务角色/人员办理。

办理继续使用原付款日期、方式、参考号和模拟确认校验；通过后移出待付款，保留在已付款列表，刷新和备份恢复后可回看。统计是当前人员可查看记录的汇总，不冒充公司总支付金额。不连接银行、不自动扣款、不生成支付指令或批量付款。

## 兼容、保护与限制

新旧单据可同时出现在统一待办；已发布新流程不改写旧路径。保护所有尚未处理的业务/财务/总账责任人和未来付款人，避免未到付款时就停用出纳。备份校验新快照、独立付款责任、总账记录与审批进度一致，缺失总账记录的待付款/已付款新单据不能导入。

当前未实现节点拖拽改上级、会签/或签、审批代理、任意条件嵌套、生产认证、会计凭证和银行接口。组织上级通过点选侧栏维护，先验证规则正确和可理解。关于“开发完成弹窗”，当前云工具无法操控用户电脑 Chrome 通知权限，不把应用业务提示当作开发完成提醒。
