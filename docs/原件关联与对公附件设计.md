# v0.23 原件关联与对公附件（2026-10-24 上海）

## 目标与范围
财务看到结构化字段后，需要回到对应原件核对；对公支付还需要验收、合同等付款材料。本轮连通“上传—关联—识别/手工采集—人工确认—审核原件—完整备份”，沿用本浏览器虚构数据范围，不接外部服务。

## 操作与业务约束
- 报销和对公使用同一附件组件，新增验收单、合同附件分类。每单5份、单份1 MB、合计1.5 MB，图片预览，PDF下载后查看。
- 原件必须先在附件区上传并分类为发票；票面采集通过下拉选择，不根据来源名称猜测。直接选图OCR、旧快速OCR仍只保留字段；两种入口的留存范围明确区分。
- 从关联图片识别时，复用已留存字节，不产生第二份文件。OCR完成只写候选，人工核对勾选后才进入票面清单。PDF可关联并手工录入，暂不OCR。取消或换原件使当前识别失效，关闭编辑终止任务；不保存原始OCR文字。
- 每个原件最多关联一张票面，合并多票PDF需拆分后上传；支持不关联原件的手工字段与旧票据。未关联明确提示，不假称原件已存。
- 已确认票面或正在编辑的候选引用原件时，拦截移除/改为非发票分类。先编辑票面、选择“不关联”、核对并保存修订，才可改类/移除。移除票面不自动删文件；已保存附件的移除仍须确认，只在保存本次单据后生效。
- 审核详情的字段卡片显示关联原件名称、图片预览和原文件下载；审核人不能修改。字段JSON含attachmentId及采集来源，不带原文件；完整备份包含文件和引用。

## 模型、兼容和失败策略
票面records增加可选attachmentId，schema沿用1；引用限定同一单据attachments中的发票类ID，文件名可同名，不影响ID关联。引用不存在、分类错误或同文件重复引用在保存/备份导入时拒绝。旧数据缺引用合法，不补造关联。

对公payments增加可选attachments。未显式传入文件/字段的旧调用在撤回重提时保留旧值；UI传入完整本次清单，可按用户意图修订。审批/总账/付款保持原文件与引用，合同收款及路径快照逻辑不变。

企业业务元数据仍限制80万字符（不计附件data）；含文件总序列化限制220万字符。附件格式、签名、扩展名、base64字节大小、数量及每单容量分别校验。完整备份仍有5 MB上限；两个业务存储合计还受浏览器实际配额限制，不保证可同时填满。先验证、setItem成功后才更新业务内存；失败保持原值与编辑内容，用户可减少本次文件重试。备份多键写入沿用回退机制，不宣称断电事务或跨页面并发安全。

## 验收与边界
真实浏览器OCR使用公开虚构样票；逐字节核对下载，验证报销关联原件备份恢复、坏引用拒绝、对公发票/验收材料与配额失败重试、主管只读、手机解除关联和原文件保留。业务测试覆盖跨重提/审批、二进制与元数据独立容量上限。最终数量、产物与发布证据见阶段验收。

不支持逐费用行分摊、多票共用一个文件、服务端归档、跨设备同步、PDF文字提取、官方发票验真或履约自动确认。保留原文件不能证明文件真实或服务已经完成；真实AI按用户选择继续暂停。
