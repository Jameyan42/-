# 数据备份、恢复和旧数据迁移

## 旧浏览器数据：先在原来源完整备份

浏览器按“来源”隔离localStorage，业务后端地址不能跨域读取GitHub Pages中的旧数据。请使用原Chrome配置，在原站点打开 `/samples/legacy-backup.html`。该只读工具不加载模拟系统、不写入或删除旧值、禁止网络连接，只将所有qingbao-*原始键和值下载为JSON，含原base64原件和实验记录。不要只使用原全局业务备份而漏掉S001/S002/R009等独立键。

下载后先另存一份受控备份，再在业务服务器的管理员页面上传。服务器原字节保存完整原备份及SHA256，可重新下载核验；先预览，再明确选择旧单号→真实员工账号的映射后导入。原浏览器内容不会删除或清空。

首版仅适配S001统一单据、支持的费用类型/有效字段及能校验的原始票据。其他旧流程、S002实验、R008演示发布记录等完整保留在原备份，不自动转成生产业务。如果某条字段不合法，预览明确标记待手工补录；不擅自编造日期、税号或真实身份。

迁入只创建DRAFT，生成新的正式单号，保留旧来源编号、状态和备份引用，不继承旧“批准/已付”。原件可校验时按字节迁入私有目录；元数据但无实际字节的旧文件不能假装已经上传。每次导入一个事务，来源唯一，重复提交不创建第二批单；失败回滚，原备份保持。

## 一致备份

应用所有业务事务获取共享维护锁。备份CLI获取同一数据库排他锁，等在途操作完成后获取数据库custom dump和私有文件快照。写入暂停期间不发生财务状态与附件相互错位。会话数据不进dump，避免恢复旧登录态。

脚本核验数据库引用的每一份附件/原备份实际存在、哈希与DB一致，再保存dump、文件SHA256、行数清单；缺原件不会被“备份成功”掩盖。所有文件名受控UUID，不跟随非普通文件。备份目录和文件为0700/0600，拒绝覆盖已存在的备份目录。

在受控运维环境设置变量：

```sh
# URL和秘密通过受保护环境文件传入，不放命令参数/聊天/Git。
# BACKUP_DATABASE_URL = 有备份权限的数据库连接（或MIGRATION_DATABASE_URL）
# FILE_STORAGE_DIR = 唯一权威附件目录
# BACKUP_DIR = 每次新的私有目录
node --env-file=.env --import tsx server/backup.ts backup
```

需要可执行的pg_dump/pg_restore。若工具在PostgreSQL容器中，可设置DB_TOOLS_CONTAINER为该容器名；CLI通过Docker环境变量传入连接凭据，不在进程参数中写密码。CLI本身仍需能连接数据库并读取权威附件目录。不要向web进程挂载Docker socket。

业务镜像不含PostgreSQL客户端。推荐在受控Linux运维主机安装同项目的Node依赖，通过私有Docker网段连接DB，设置DB_TOOLS_CONTAINER调用同版本DB容器内工具，FILE_STORAGE_DIR指向经授权的权威命名卷目录。运维人员可通过docker inspect获取该主机上的DB私有地址和卷挂载点；这些权限只交给运维，不交给web进程。若使用主机工具，pg_dump版本不得低于服务端。必要时停止app，在保留命名卷条件下备份DB和原件，不允许只有SQL、没有原始文件。

## 恢复：只恢复到新空库和新文件目录

```sh
# RESTORE_DATABASE_URL = 事先创建的空库，不得指向唯一生产库
# RESTORE_FILE_DIR = 新的目录
# BACKUP_DIR = 备份目录
node --env-file=.env --import tsx server/backup.ts restore
```

先验证dump和每个文件哈希。数据库非空则拒绝执行；不自动DROP、TRUNCATE正式业务或覆盖已有目录。恢复后比较所有业务表行数、每份文件的哈希和DB引用。会话不恢复，用户重新登录。随后用迁移工具核验SQL版本并授权应用角色，再用新连接和新附件路径启动服务。

务必验证：员工能看原单、财务权限正确、已付记录与审批历史存在、私有附件能下载且哈希一致、无权限用户仍不能看。核验后再安排维护窗口切换，并保留原库与原卷作为回退，不把“pg_restore退出0”当作完整恢复证明。

## 定时与留存

提供deploy/backup-nightly.sh及systemd service/timer模板，生成时间戳目录，默认计划当地02:00。需要运维人员配置专用账号、保护的环境文件、备份根目录、失败告警和加密留存，再明确启用。本环境没有安装或启用真实服务器定时任务，不声称已建立异地灾备。

备份可能包含姓名、金额、票据和密码哈希，软件没有自动加密备份或自动上传第三方。真实使用应启用加密磁盘/受控加密备份，按授权保留期限管理、定期演练恢复。删除与留存由公司批准，本轮不自动删除旧数据、原件或备份。

## 已实际验证

在独立开发PostgreSQL16中生成备份，恢复到另一个新数据库和新文件目录，行数与文件哈希核对通过；用恢复服务重新登录、读取已登记付款单/审批记录和下载原字节，均实际检查。另重启PostgreSQL和测试app容器后验证原单据、付款历史和原件仍保留。测试均使用虚构资料，不是正式企业灾备验收。
