1. **服务端测试：21项通过**（15项真实HTTP/数据库测试，含1父+14子检查；另3项北京时间日历边界、3项安全配置测试）。没有用内存数据库或写死接口结果。北京时间凌晨、午夜前和跨月/跨年都实际断言，避免把中国日期误判为UTC的“未来日”。
   - 已有用户库不能重新bootstrap；初始密码强制修改。
   - 原件字节、草稿在退出重登后保留；其他员工不能读单或下载。
   - 无登录、缺CSRF、伪造审批、提前付款被拒绝。
   - 两个审批并发只有合法当前动作成功，不跳过财务。
   - 财务退回→修改→重提→原单发票不自匹配，版本和操作保留。
   - 两次同一付款登记只有一条记录；原审计/付款SQL修改删除被拒绝。
   - 两张独立单同时争用相同发票，只有一张提交成功，失败方仍是草稿。
   - 乐观版本冲突、伪造文件类型和XML外部实体被拒绝。
   - PDF/PNG/XML/OFD原字节实际上传/下载；OFD只校验容器/保留下载，不宣称能预览或验真。
   - 旧“已付款”备份明确映射后只能产生草稿，原备份字节保留且重复迁移不再创建。

   - 已驳回不能前端恢复，明确释放制度下其他单可以再次申请未用发票。
   - 付款信息更正追加，原记录不覆盖；停用账号会话立即失效。

## 测试中发现并处理

- 首次npm缓存目录不可写：改为临时专用缓存；未更改HOME或获取额外权限。
- PostgreSQL首次启动尚未就绪：等待可连接后执行迁移，Compose提供健康依赖。
- pg驱动将JS数组默认编码为PG数组而非JSONB：显式JSON序列化审核结果，之后实际提交/审批/并发测试通过。
- 改密码同时增加auth_version会使后置审计误认权限过期：把权限锁定审计放在同一事务的密码修改之前；首次改密及其他会话失效均复测。
- 备份工具首次pg_restore缺显式目标参数：修复后恢复到新空库，未覆盖原库；再次增加原件DB引用核验并实际复测。
- 私有目录不能配置到public/dist，Vite开发服务也拒绝.data/备份/密钥路径；实际对开发服务的私有测试数据路径请求返回403。真实资料仍应放在项目目录外，并只通过受控后端运行，不能用Vite开发服务器承载正式财务。
- 同来源与跨来源浏览器备份不能混为一谈：增加原域名的只读备份工具，业务页面提示跨域限制；测试确认不写入旧模拟数据。
- 常规构建网络失败没有伪造成功结果；使用明确标注的预打包路径实际构建/运行。

- 没有真实服务器、域名证书、境内地域/备案适用核查或真实企业签字验收；不接收未经授权真实财务资料。

- 数据/备份软件层没有自动加密或异地复制，须由运维提供加密磁盘/备份、监控和留存制度；定时器仅提供模板，未在正式服务器启用。

- 原件物理保留；解除关联只写记录，不删除原字节。留存到期删除、撤销/差额付款、金额冲销及更复杂企业审批不在首版。
- 当前仅支持CNY，不支持多公司/外币；列表按北京时间创建日筛选。
- 原政策维护暂为有校验的管理员JSON，不宣称财务规则均已具备可视化生产配置；R005—R010原演示能力保留，未全部接入服务端。
