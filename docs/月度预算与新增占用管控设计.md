# v0.26 月度预算与新增占用管控（2026-10-24 上海）

## 为什么今天优先补这个核心模块
已有申请、报销、具名审批、对公和模拟付款闭环。预算仍是所有月份共用的软预警，难以清楚演示“事前控制—预留—核销—实际支出”。本轮收敛到单企业、部门与月度预算，补独立额度、新增占用硬控和贡献明细，不继续扩展真实集成或复杂会签。

## 预算口径
本月占用 = 已付款报销 + 未完成报销在途 + 已批准申请的未核销余额。

申请1000元批准后预留1000；关联报销265后为报销在途265 + 申请余额735，总占用仍1000。付款把265从在途转实际，不再增加；结束申请释放735，最后保留实际265。退回/撤回关联报销，会使占用回到申请余额，不等于直接释放部门预算；未关联报销退回/撤回才直接释放其占用。草稿、待审批申请不预留。

按报销原提交日期归属月份、申请计划月份预留，沿用现有同人/部门/月/类型及申请上限校验。金额内部按分比较；预算明细每条“贡献金额”之和等于占用总计，不把批准申请总额再加一次。预算不含对公，后者仍使用合同额度；也未扩展多法人、费用类型预算或跨月摊销。

## 月度配置及控制点
- 财务可按部门和月份设置额度0～1000万元、软预警或拦截新增占用，原因5～200字；记录明确人员、配置前后值、版本及上海展示时间。
- 已配置月份独立；其他月份继承已有默认额度并软预警，不静默迁移旧历史。调低额度可使余额为负，但不撤销已有预留或付款。
- 硬控判断必须同时满足：所选月为block、变更后占用大于变更前、变更后超过额度。只在报销正式提交/重提和申请最终批准产生新占用时执行。
- 申请中间节点批准仍未预留，不在该节点提前扣预算；最终批准不足时不保存新审批记录。超额报销可保留草稿和编辑内容，不能正式提交；财务调整后可重试。
- 已预留申请转报销、在途转已付、释放占用均不属于新占用，降额后仍可继续。审批通过并不修改报销金额，对公不绕用员工预算。
- 当前为同一浏览器内的提交前比较，不是后端并发占用锁。多人同时提交、追加/冻结审批、跨法人资金控制仍需服务端设计，不能以本原型代替真实预算管控。

## 查看与下钻
预算页显示额度、来源、模式、实际、报销在途、申请剩余和余额。可查看本月调整历史、导出本月汇总CSV。下钻明细区分报销和申请，申请只列正的剩余预留；每页20条，导出所有匹配贡献记录，从每条可打开原单。

每月总量与贡献明细分别解释“钱在哪里”；表格里的批准总额/已核销仅解释申请，不再次参与合计。历史零贡献和已关闭申请仍可从原申请页面回顾，不放在当前占用明细中。

## 存储、迁移与异常
新增可选budgetControl：schema1/version、periods及history，最多240个部门-月组合、500条调整记录、40万字符；旧budgets默认额度保留。导出完整备份包含新配置，version=1兼容旧文件；旧备份缺新字段时保留当前月度设置，恢复前明确说明。若当前配置损坏，旧文件不能假装补全未知月度配置，需有效完整备份。

默认预算及月度配置坏数据保留原始值，统计标不完整，暂停编辑/导出与新增占用；草稿和非新增占用处理保留原业务范围。配置先校验、持久化成功后更新内存，配额失败不覆盖旧值和填写内容。组织更新不得借默认回退值覆盖无法读取的预算。恢复沿用多键回退，不宣称断电事务和跨标签并发安全。

## 面试展示与验收
在全新无痕空间，初始产品部占用3860元；配置本月4860元/block，陈嘉申请1000后占满，另交1元普通报销被拦。关联申请提交265元、按财务分工完成部门/财务/总账/模拟付款，申请余额735；结束释放后总占用4125、可用735。实际环境有其他数据时，应以当前占用为准，不套用固定数字。

另验证调低到3970后，已批准申请仍能核销和付款，结束后不倒退原业务；多月份独立、最终批准失败不留处理记录、备份新旧兼容、损坏配置/配额保护、25条明细分页和CSV、手机布局。最终证据见阶段验收。
