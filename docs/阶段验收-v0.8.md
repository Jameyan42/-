# v0.8 组织架构与审批流程树验收

组织部门树与人员汇报树；部门/人员新增与编辑；管理员角色与具体模拟身份；报销、费用申请的金额/类型条件分支及顺序节点；直属主管、部门负责人、指定人员；草稿、路径试算、发布版本；具体人员审批及路径快照；在途人员保护；组织/流程备份和旧数据兼容；六条演示指南、需求文档、面试案例与 PDF。

## 验证

- 31 项 Node 业务测试通过，新增 6 项覆盖循环/失效引用、金额边界/类型/去重、全部人员路径校验、逐人顺序与越权、版本快照、在途及待付款保护。
- 28 项 Chromium 浏览器场景整套通过，其中新增 6 项。覆盖申请两位主管审批后才预留、不同同角色人员不可越权、组织变更不改旧路径、草稿/发布/只读隔离、创建部门/负责人/员工、零预算、新旧备份、损坏配置恢复、指定跨部门人员审批报销到付款，以及手机宽度。
- 原有真实 OCR 样票、旋转裁剪、异常回退、申请核销、草稿撤回、风险退回、财务付款等场景继续通过。
- 构建与单文件导出成功。最终生产 HTML 在本地同构 `/-/` 路径验证：人员路径试算、4000 元申请两级审批、手机布局，无浏览器脚本错误；项目案例 PDF 重新生成。
- 手工检查桌面审批树、部门树及手机汇报树截图。分支使用连接线表达分流与汇合，手机将互斥分支纵向排布。

## 联调修正

补充待付款阶段的财务人员保护；非管理员始终查看已发布流程，避免将管理员未发布草稿误当运行规则；恢复备份时补齐零预算并更新编辑草稿；包含组织的备份恢复前校验保留申请的部门引用。用具体模拟身份记录操作日志。

## 限制与复盘

树形表单编辑，尚无拖拽、会签/或签、任意嵌套条件、转交/代理。没有后端认证、数据同步或防篡改审计。旧单据无路径快照，继续原固定角色逻辑；首次运行不清理旧数据。为保持现有名称关联，现有部门及姓名暂不能改名/删除。真实用户试用尚未实施，测试通过不证明业务效果。

云端 Chromium 的公网证书链限制未绕过：交互验证使用本地同构生产产物；线上发布通过 Pages 状态及 HTTPS 下载散列确认，不宣称已经完成线上浏览器交互测试。
