## 后续优先级
1. **可用性验证实施**：任务与记录模板已备好，获取参与者亲自试用反馈；没有反馈前不要宣称调研结论。
2. **录入体验**：按反馈决定图片旋转、裁剪或多张票据；先覆盖少量明确类型，避免通用 OCR 准确率承诺。
3. **面试演示稳定性**：更多异常输入、不同设备与无网络情况下的提示；更新真实测试证据。
4. **需求评估后再决定**：PDF 首页面渲染、历史规则快照、独立月份预算、后端与真正权限。

- 发票验真和支付需要外部服务、凭证与合规设计，不在当前免费原型中模拟成功。

- 数据保留在浏览器，更新脚本不执行数据重置。不能以重置或清缓存作为常规升级步骤。
- 不把功能数量当作项目成果；优先用完整闭环、明确取舍和可复现验证支撑面试叙述。
