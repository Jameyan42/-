# 员工报销进度总览设计

## v0.14：员工报销进度总览

入口：选择员工角色及具体人员 → 报销进度（员工工作台也提供入口）。按流转中、待我完善、已登记付款分组；卡片显示申请金额、当前节点、当前待处理人、提交时流程版本和有序路径。搜索事项/单号/状态/节点/待处理人，每页10条；改变分组或搜索回到第一页，切身份/页面清空筛选。概览数字始终为本人全部报销，匹配数单独显示。

快照单据按申请人ID归属；无快照旧单/草稿仅在姓名唯一且部门匹配时归属。不按当前组织推测旧单审批人。当前具名路径来自提交快照，人员已停用/缺失或角色变化会提示核对，不自动改派。草稿/撤回/退回归入待我完善，退回显示最新可用说明，经查看详情可修改重新提交；重提后采用新快照。已付款不再显示待处理人，也不表示真实银行到账。

演示：林晓提交200元报销 → 报销进度查看赵航及后续周宁 → 赵航退回并注明补充用途 → 林晓在待我完善查看原因并修改提交 → 回到流转中。财务分工模板下叶禾的单据可依次显示沈岚、周宁、高璇和杜川。不要用演示身份选择宣称具备生产认证；当前没有催办消息、处理SLA、到账确认或事前申请进度总览。

## 范围与产品取舍

目标是让员工回答“谁正在处理、我是否需要补充”，使用已有流转记录和详情编辑能力，避免增加仅展示状态的重复清单。进度页不提供审核按钮，不发送催办，不根据提交时长臆造超时。付款节点独立于审批节点：旧快照由原财务登记，新财务分工快照由指定付款人员登记。全部审批节点通过仍会显示待付款。

图示仅表示本次提交的路径：已通过、当前待处理、后续节点；不是业务发生时间线。退回后不再将未完成路径画成正在等待，修改重提会生成新的提交快照；历史仍可在详情查看。已登记付款仅说明模拟记录完成，不能替代真实银行到账状态。申请金额分组汇总不是期间费用支出指标，草稿也计入待完善申请金额。

归属优先使用快照申请人ID，旧单姓名/部门双重匹配仅作兼容；无法可靠归属时不展示，不修改源数据。详情入口增加本人校验。此保护只针对本页与详情入口，其他分析菜单不是生产访问控制，当前浏览器持有全部演示数据。身份选择不等于登录认证。

## 验证与复盘

业务测试覆盖ID优先、姓名部门及歧义、停用角色、schema1/2责任人、待付款独立阶段、异常状态、退回说明、排序和不修改数据。浏览器覆盖换人清筛选、退回重提、总账/独立付款、分页重置、手机空态与转义。单独运行同构生产产物的真实提交和退回重提，避免只依赖预制记录。

本次先统一职责和状态含义，再展示路径；没有做真实员工研究，不宣称减少催问次数或缩短审批时间。后续候选为费用申请进度的同口径整合，需要先明确预留、核销和结束状态，不直接复用报销付款模型。
