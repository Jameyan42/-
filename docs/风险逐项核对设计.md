# v0.25 报销与对公风险逐项核对（2026-10-24 上海）

## 产品目标
规则预审已经能指出疑点，但后续审核人还需要知道“前一人核对了什么、缺哪些材料、依据是否仍有效”。本轮让核对说明与具体命中的规则关联，保留人工判断和依据变化。不是AI审核，也不新增审批豁免。

## 范围与交互
- 报销和对公详情在当前预审下方增加风险逐项核对。当前节点具名处理人可追加“已核对 / 待补充 / 建议退回”，说明5～500字，可关联一份本单已保存材料；其他人员及已结束单据只读。旧无快照报销沿用原角色处理，记录当前明确人员，不追补旧核对。
- 每条记录保存人员ID、当时岗位、节点、时间、结论、说明、关联材料名称、提交轮次、流程版本及该疑点的规则参数/触发依据。核对与审批分别保存，核对不改金额、审批游标、合同占用或站内消息事件。
- 当前疑点显示同规则最新说明及有效性；全部历史按新到旧展示。可以多次补充，不覆盖或删除旧结论，不把核对次数当作已解决疑点数。
- “已核对”只表示记录了人工核对说明。当前拦截仍由规则计算，财务/总账/付款通过继续受限；“待补充 / 建议退回”也不会自动退回或自动审批，处理人仍需明确执行对应动作。当前不强制每项都写记录才审批。
- 当前记录可导出CSV，包含当时金额/日期、结论、说明、关联材料、人员/节点、版本/轮次及当前有效性。按保存记录导出，未保存输入不在CSV中。
- 单独的核对编辑区有未保存提示；审批前先保存或放弃本次未保存填写。保存失败保留输入；放弃只清空本次候选，已存记录不删除。审批处理备注与核对说明分别保留，防止保存一种内容误清另一种内容。

## 依据变化识别
浏览器用Web Crypto SHA-256生成变更对比标识，覆盖单据业务字段、提交路径及原件实际字节，以及当前政策和该命中项的显示依据。忽略纯检查时钟、审批游标/状态、历史、已存核对及后续总账/付款登记字段，避免正常节点推进使说明无意义地失效。

修改金额、用途、原件、票面、审批路径/重提轮次，或任何规则配置变化后，旧说明可能变为“依据已变化，需重新核对”。若规则不再命中，仅展示“当前未命中，仅保留历史”，不推断风险已解决或文件真实。相同名字、大小的文件替换了字节也会被识别。规则版本变动整体要求重新核对，这是当前采取的保守策略，未做到只使受影响规则失效。

这只是本地变更检测，不是签名、可信时间戳、防篡改审计或税务验真。核对快照保留当时选定规则、金额/日期及依据，不构成所有旧业务字段和旧文件的完整归档；用户后续移除材料时，历史仍保留当时名称并标注当前文件缺失。

## 模型、权限与异常
可选doc.riskReviews数组，每单最多100条、序列化40万字符，超限不自动删除旧数据。旧记录缺此字段合法。数据类型限定expense/corporate，验证单号、规则ID、人员/时间、结论、说明、SHA标识和预审快照。riskReviews独立于审批history，不生成“我已处理”次数或新的消息已读事件。

报销重提与对公重提均保留旧核对，新的提交轮次令其失效。核对字段纳入报销持久化、企业业务及完整备份校验，沿用version=1格式和存储键；非法记录拒绝导入或保存，不清空原值。报销总容量保护同时覆盖附件及核对，企业元数据/总容量和5 MB完整备份限制保持原样。

异步计算完成前后检查页面仍在、单据对象及处理人未变化，避免关闭或切换后保存到错误对象；不宣称支持跨标签并发。相关规则、组织或企业数据异常时暂停追加与导出，当前有效性标未知；坏核对记录只提示恢复有效备份，不自动覆盖。持久化成功后才替换业务内存，配额失败不改变旧单、审批或输入。

## 演示路线
1. 员工提交只有酒店水单、无发票原件的虚构报销，主管对“缺少票据”记录已核对和关联材料，状态仍待主管；主管再明确通过。
2. 财务看到上一节点说明，再补充自己的核对；即使写了已核对，原固定缺票拦截仍阻止通过，可明确退回补材料。
3. 员工修改金额重提，主管看到旧记录需重新核对。新说明追加保存，旧200元与新201元的核对快照分别可查；更新规则版本也会令旧说明失效。
4. 对公大额规则阈值50元、拦截，提交100元虚构单。许明从统一待办核对并转交，周宁从消息中心核对，财务通过仍受拦截；备份恢复后核对记录、处理历史和原件仍可查。

## 继续保留的边界
没有核对任务分派、员工材料补交通道、风险豁免审批、按组织制度适用范围、后端协作、官方验真或真实AI。可用性、误报率及收益未经过真实用户验证，页面和测试只使用虚构资料。汇联易参考界面暂缓，未要求用户提供难以脱敏的截图。
