## 功能及数据

新增法人字段companyId，与部门/报销人分开；三份模拟法人深圳/东莞/上海，虚构税号DEMO-SZ-001、DEMO-DG-001、DEMO-SH-001。法人有标准名称、税号、启停状态、有效起止日，历史别名支持名称/可选历史税号/起止日。配置使用已有qingbao-s001-v1的可选entityConfig，不建立新数据库或键。

每票新增可选recognitionStatus（已人工核对/待核对/识别失败）、recognitionConfidence（整体OCR分数，非字段真实性概率）、buyerTaxStatus（未确认/已确认/票面确为空），保留原source手工/OCR辅助区别。OCR结果自动标为待核对，不能因重新打开表单就变成人工确认。缺字段旧单可读取，不默认为已做过R004。

默认企业票据政策为本作品的明确模拟制度：一般数电/电子普通/电子专用/纸质票要求企业抬头和购买方税号。不是通用税法结论。明确模拟客运特例R004返回NA；“其他”没有确认政策则信息不足，不自动豁免。R004不适用不代表R002等其他规则也适用或通过。

匹配采用有限NFKC及名称首尾空格、税号空格/大小写规范化后的完整比较。保留城市、有限公司、分支标识，不模糊认定法人；不根据税号前缀判断，不使用销售方税号替代购买方。

## 判断与逐票展示

- 正确标准名＋税号通过；日期内匹配明确授权历史名称/历史税号可通过，展示授权区间。
- 税号正确但名称未获当前开票日有效授权，人工复核。
- 可靠票面属于其他法人、名称正确税号明确错误、名称税号均错或不符合企业抬头的个人票据，拦截。
- 尚未核对的OCR差异先人工核实；未知或低整体置信度不能当作已确认错税号。即使高整体分数，原始OCR仍需人工核对才作可靠事实判断。
- 购买方名称缺失、税号未知未识别、识别失败或日期不足，信息不足，返回字段列表；只有明确确认原票确空且适用政策要求税号时拦截。
- 每张票分别输出结果、购买方/税号、基准法人/登记税号、依据、缺失字段和建议；聚合ERROR>BLOCK>信息不足>REVIEW>PASS>NA，其他票的PASS不能抵消BLOCK。

法人/政策版本随新批次存到context，R004逐票结果另有配置版本和法人/授权依据。修改当前配置不改旧快照；旧三规则批次只显示原三结果，明示未执行R004，不偷偷补写。

## 人工处理与变更留痕

复用财务最终通过/驳回：人员意见必填，BLOCK/信息不足/ERROR不允许普通放行，本期不做复杂例外授权。REVIEW经核查后可有意见批准。

新增同区核查动作“需补充材料”“已核实信息”，保存当前批次、输入快照、财务人员、角色、意见及时间，不覆盖自动结果、不改变批准状态。信息不足需补正字段再审。

编辑已审核资料必须填修改原因；记录修改前/后完整输入、人员角色、时间。改变companyId、购买方名/税号或核对状态均让当前审核失效并清除当前批准，旧批次和原财务结论保留。法人配置修改也记录前后配置、角色、时间、原因，新版本号递增；新增记录受本地容量限制保护。

## 演示操作

入口仍是 https://jameyan42.github.io/-/?view=claims 。本地`npm ci`后`npm run dev`，打开`http://localhost:5173/?view=claims`。

1. 报销单管理→新建→载入正常模拟案例；所属公司深圳，票面为深圳标准名及DEMO-SZ-001，四规则可一次执行。
2. 将购买方改东莞公司，税号改DEMO-DG-001→开始自动审核；在R004逐票表看到“另一法人”拦截和标准/实际信息。
3. 切换财务，填写核查意见，可记录“已核实信息”，普通通过仍受BLOCK限制；填写最终意见后驳回。
4. 编辑原单，填写修改原因，改正确公司或票面；保存后当前审核失效，重新审核生成新批次。审核历史仍有旧结论、人员时间与修改前后记录。
5. 对比税号空且未确认（信息不足）与人工核对＋票面确为空（拦截）；特殊模拟票R004 NA不豁免其他规则。
6. 财务→审核规则→模拟法人及票据政策JSON，可维护带起止日的历史名称，填原因保存；新审用新版本，历史结果不变。

## 边界

仍为单浏览器模拟，前端角色不是生产鉴权；配置编辑器是JSON，不是复杂企业主数据平台。没有官方税号格式、联网注册信息或税务验真。高置信度不等于真实性；默认要求人工确认OCR。旧S001缺法人/核对状态的资料不自动补成正确企业，新审需补齐。

仅R004对新增特殊票类型有确认政策，原R002类型范围未被暗中扩展，其他规则可能仍要求补资料。旧主应用的单一抬头配置、预算/付款和备份边界维持原状，不虚称已全部统一。已审修改原因变为必填是本需求的明确变化。
