# v0.28 阶段验收：差旅城市/人员职级预审

日期：2026-10-24（Asia/Shanghai）。

## 交付

现有“差旅标准”升级为财务可维护的制度：城市目录、两城市档×两职级档标准、单城市/职级特例、人员ID职级、住宿/餐补/市内交通及缺水单/未关联事前申请5类提醒或拦截。员工自动匹配城市/人员职级，不自行选高档；未知分类明确提醒。

新报销保存提交标准快照，在途按快照预审，退回重提才用新标准。详情显示标准计算、实际金额和超额；市内交通同日多行合并。规则命中进入已有预审、核对留痕和财务/总账/付款门槛，说明不豁免。旧单不补造新快照，备份兼容、存储失败/坏数据保护同步完成。详见[业务与取舍设计](差旅城市职级预审设计.md)。

## 测试

- 168项单元/业务测试通过，本阶段新增9项：城市规范化/未知回退、人员ID绑定与忽略自选高档、财务发布及城市特例优先、参数/容量/旧policy兼容、金额分币边界/零标准/交通拆行合并、5类预审及财务/总账/付款拦截、快照与当前制度分离、旧单提示、备份与坏快照、关联行程/职级变更不放松物理行程和额度。
- Chromium整套131项场景通过，本阶段新增6项：城市/特例/人员匹配只读；硬控/改制度不改在途/退回重提与处理历史；交通合并/餐补及材料风险；容量失败/旧备份保留制度/坏快照拒绝；未维护分类与未发布切换/手机；坏制度暂停提交及坏快照仍可查看而财务不能通过。
- 原差旅及通用预审10项场景在开发阶段先回归通过；最终整套包含这些场景，不将重跑数量累计为独立测试数量。
- `npm run export:demo`构建及单HTML导出成功，未引入新依赖或外部收费服务。

## 最终生产同构验证

构建后的单HTML配套资源，在真实`/-/`子路径使用浏览器操作：

1. 管理员发布财务分工，财务发布住宿超标硬控、陈嘉管理档，保留其他规则。
2. 林晓杭州至上海市3天2晚，系统匹配上海/普通档；留存虚构发票PDF与虚构酒店水单PDF，手工录住宿1100/2晚、餐补300/3天、同日交通50+40，不调用OCR。
3. 主管转交，财务看到住宿标准500×2=1000、超额100，交通同日90对80、超额10；财务通过被拦，单据原值未改。
4. 财务退回，员工修正住宿1000元后重提；部门总→财务→总账填科目/归属→指定付款人员登记模拟付款1390元。
5. 最终已付款，旧住宿风险及新处理时标准/结果仍留存；完整备份包含差旅制度和提交快照。

桌面和390px手机页面已查看，表格在容器内横向滚动，整页无溢出。零页面JS错误，只有同源GET资源请求，无上传/外部模型，不依赖OCR。这里是本地生产同构浏览器交互；公网部署另行核对HTTPS产物，不宣称公网自动化操作。

## 文档、复盘与边界

需求、打开指南、差旅设计、面试案例、项目待办和Excel迭代表更新。演示ZIP增补差旅制度说明，逐项核对与最终源文件一致；既有项目案例及面试PDF继续作为通用手册，最新差旅流程以本阶段设计及网页为准。
