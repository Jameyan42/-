# 小样本可用性测试：任务与记录模板

本文件是测试计划，不是已发生的访谈结果。计划邀请员工、主管、财务各 2 位，共 6 位参与者；未招募时不填入虚构反馈或数据。

## 测试准备
- 只用公开虚构样票和模拟业务背景，不收集真实票据、银行账号或个人敏感信息。
- 向参与者说明这是个人原型，测试的是设计而非其操作能力；记录前获得同意。
- 每位参与者使用独立浏览器访客窗口，保留现有演示账户数据，不要求清除其他人的记录。
- 记录测试设备、网络、首次模型加载时间；将 OCR 模型下载与后续识别时间分开。
- 主持人先不指路，参与者停顿时记录，再询问其预期；需要提示才能完成的任务单独标记。

## 员工任务
1. 你完成了一次客户拜访，需要报销 268.50 元。使用提供的虚构样票，提交报销并说明用途。
2. 提交后发现号码有误，请在允许的阶段修正，并找到修正后的处理状态。
3. 你还没有写完另一笔报销，希望下次继续。请保存并重新找到它。

## 主管任务
1. 找到待你处理的报销，查看费用依据并处理一笔正常单。
2. 你认为一笔费用说明不足，请要求员工补充，并找到你的处理记录。

## 财务任务
1. 找到疑似重复票据，说明你认为它为什么有风险，以及你会如何处理。
2. 在正常审核后完成一笔模拟付款登记，并找到付款参考信息。
3. 解释销售部的已付款、在途占用和可用余额分别代表什么。

## OCR 对照任务
参与者分别使用手工录入和 OCR 辅助录入完成同类虚构样票。交叉安排两种方式的顺序，减少学习效应。记录正确提交所需总时间、号码错误数、金额错误数、人工修正次数、是否理解“核对后应用”。不要以样票成功次数推导真实发票准确率。

## 指标口径
- 任务完成率：无帮助正确完成的任务数 / 有效尝试数；辅助完成与失败分别列出。
- 提交耗时：从读完任务到成功提交，单位秒；标明是否包含首次模型下载。
- 输入错误：与指定虚构样票相比的号码和金额差异，按字段记录。
- 预审理解：让参与者用自己的话解释提示原因与下一步，记录原话再判定，不只问“看懂了吗”。
- 返工次数：完成任务前发生的退回、撤回或再次修改次数。

## 复盘与下一步
按“观察 → 可能原因 → 设计修改 → 再验证”记录。6 人小样本用于发现问题，不用显著性语言证明业务效果。优先处理阻断任务的失败和误解，再处理耗时与视觉偏好；将未验证的解释明确标为假设。
