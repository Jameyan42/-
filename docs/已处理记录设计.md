# v0.11 我的已处理记录

## 问题与方案

统一待办在操作后移出单据，审批人需要回看“我处理了什么、当时怎么处理、现在进行到哪里”。在审批中心提供“待我处理 / 我已处理”双视图，侧栏角标仍只统计当前待办。已处理视图按具体人员标识归属，支持报销/费用申请类型、通过/退回驳回/付款登记结果筛选，关键词搜索、最早/最新处理排序、每页 20 条分页，以及当前筛选结果全量 CSV 导出。

## 记录口径

一条记录代表一次成功的处理操作，不代表一笔单据。费用申请通过/驳回、报销业务审批/财务审核/总账复核/退回、付款登记均可记录。员工保存、撤回、结束自己的申请不是审批操作，不列入本人的审批已办。越权、未填总账信息、付款校验失败等未成功操作，不创建成功处理记录。

同一报销可先被退回、重提，再次通过；同一财务人员在旧流程中可先审核、后登记付款，两次分别保留。页面显示“处理次数”，不汇总这些记录金额为支出，避免重复处理被误解为多笔费用。

## 具名操作结构

在原 history 条目内新增可选 operation 对象：schema、单据类型、actorId/actorName、当时角色、动作、节点与标签、ISO 处理时间、处理前/后状态、备注、流程版本、提交快照时间标记，以及处理时单据摘要（事项、申请人、部门、费用类型、金额）。总账通过额外保留科目/核算归属，付款登记额外保留付款日期/方式/参考号。

处理时摘要独立复制，后续修改报销事项或金额、退回重提、改变审批版本均不会改写过去记录。“处理后状态”和“单据当前状态”分开展示；点击“查看当前单据”打开最新详情，不将当前详情冒充历史版本。提交快照时间用作轮次参考，不声称全局唯一业务流水号。

## 人员与历史兼容

按 actorId 精确匹配当前模拟人员，不按“同为主管”、姓名字符串或日志措辞推断。旧日志没有 operation 时保持原样可在详情回看，不自动补写归属和时间。升级后实际处理旧单据时可以开始具名留痕；其版本标记为“历史固定流程”。同一人员后来角色变化，仍可查看自己过去的操作，并显示当时角色。

操作记录存储在各单据已有历史中，因此刷新、完整备份和恢复可保留；无需新增独立业务数据仓库。新增可选字段向后兼容旧备份。导入验证人员字段、角色与节点关系、动作与状态、时间/版本、处理时摘要及会计/付款摘要一致性，拒绝畸形元数据。

## 可用性与异常

切换人员/角色、筛选和搜索后回到第一页。分页只影响屏幕显示，导出当前筛选的全部匹配记录，CSV 防止常见公式注入。申请存储异常时明确说明列表不完整并禁止假完整导出，不覆盖损坏原数据。没有记录时解释“升级后的具名记录才进入已处理”，而不显示虚假的历史审批量。

## 边界与下一步

仍是浏览器虚构演示，不是生产账号鉴权、防篡改审计、会计档案或后台通知服务。旧日志不回填，记录归属范围比“所有历史业务”窄。没有真实参与者使用效果或效率提升数据。

下一步优先收集管理人员对图形组织维护、处理记录可理解性及财务分工的实际反馈。可评估处理日期区间、导出字段选择或组织画布检索；先明确场景，再增加交互，不直接扩大到会签或真实财务系统。
