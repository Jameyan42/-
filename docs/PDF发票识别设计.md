# PDF 发票识别：范围、流程与验收

更新：2026-10-24（上海），v0.27。

## 解决的问题

此前可以上传或关联PDF，却必须自行转图后才能识别，常见电子发票在录入链路中断。本阶段复用已有OCR、票面结构化、人工确认、抬头/金额/重复预审，不增加独立菜单或外部服务。

## 流程与交互

报销快速入口、报销和对公结构化采集都接受PDF。浏览器读取文件→PDF.js加载文档→展示总页数及所选页预览→用户选择页码→本页转图→本地Tesseract.js识别→候选字段→人工修正并明确确认→继续原提交审批流程。快速入口仍能旋转、裁剪所选PDF页，原文件不改变。

每次只识别一页，不汇总多页金额。换页清除未确认OCR候选，已经填写的申请字段与已确认票据清单保持。结构化候选加入不改变申请金额；快速入口在勾选后应用非空候选。已保存来源名称包含“PDF第N页”，不将OCR原文写入存储。

PDF电子版和扫描版都采用页面渲染后OCR。当前不优先抽取文本层；这样可复用保守提取和人工确认，但识别耗时及文字准确率仍受渲染、版式和OCR影响。不能把一张虚构样票的结果泛化到所有PDF。

## 原件与多票关系

要留存原件，先在报销/对公附件区选择“发票”上传，再选择关联原件和识别页。保存后保留原件引用，审核人下载原文件核对，完整备份保留原字节。直接选PDF识别只存字段及来源，不保留原文件。

沿用每单最多5张票面、一原件一张票面的约束。多页可能是一张票据，也可能是多张；系统不猜测。多票合并PDF须先拆分再上传，不将不同票据的金额静默相加。选择第2页不等于系统已审核其他页。

## 本地处理与资源

固定锁定`pdfjs-dist` 5.4.624，运行时PDF模块、Worker、CMap、标准字体和解码资源来自站点同源`ocr/pdfjs/`；随构建准备资源摘要和Apache许可证，不加载外部CDN，不调用模型API或上传文件。PDF脚本/链接动作不执行，关闭XFA及动态求值。

页面渲染长边最多2200像素，按需预览1200像素；单次处理一页，读取结束销毁PDF文档、Worker及临时画布。读取30秒超时，整次OCR90秒超时；取消、换文件、换页、关闭时使旧结果失效，迟到结果不回填新表单。浏览器本地处理不等于生产级文件安全扫描或存储安全体系。

## 限制与异常

- 识别文件最多6 MB、20页，超过需压缩或拆分。附件保留容量独立，仍为1 MB/份、5份/单、1.5 MB/单。
- 加密文件提示用户先自行解密，系统不索要或保存密码。
- 损坏、空文件、页码越界、资源加载失败提示重试或手工录入，原申请字段、已确认票据及已保存文件不变。
- 只支持现有人民币正数票面提取；红票、外币、二维码、复杂合并票自动拆分、税务真伪核验不在本阶段。
- 在线版或配套静态资源的HTTP服务可用；直接打开单HTML的`file://`仍需用在线版识别。

## 演示与验证

识别区可下载`public/samples/demo-invoice.pdf`：第1页封面，第2页为虚构扫描发票。选第2页，预期候选为265.00元、购买方星河科技及号码22345678901234567890，人工确认后加入。另有电子文本PDF测试夹具，预期106.00元及另一票号，避免仅验证图片套壳。

验收覆盖真实OCR、原件引用及字节一致备份、未确认不改金额、换页清候选、手机预览、加密/超页/坏文件/资源失败、取消及关闭后迟到保护；既有图片及审批预算继续回归。具体执行结果与部署记录见《阶段验收-v0.27》。
