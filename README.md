# 轻报 · 费控产品经理作品

在线体验：https://jameyan42.github.io/-/

面向 200 人成长型企业的中文响应式网页原型。支持员工报销、主管审批、财务审核、付款登记、规则预审、预算预警、发票关联台账、草稿与撤回、操作记录和备份恢复。使用虚构数据，尚无真实客户、业务运营指标或生产级身份系统。

## 本轮：真实浏览器 OCR

员工 → 新建报销 → 选择 PNG/JPG/WebP → 按需旋转、裁剪 → 识别图片 → 核对候选号码和金额 → 勾选确认并填入。也可点击“载入虚构样票”。

引擎为 Tesseract.js，模型与 Worker 由同一站点提供，无外部 OCR API、无密钥、无图片上传。首次按设备加载约 10 MB 数据；浏览器只保存字段、附件名称与核对来源，不保存原图或识别原文。OCR 不等于验真；候选提取可能失败，必须人工核对。PDF 暂不识别，仍可手工报销。

## 运行与验证

需要 Node.js 20.19+ 或 22.12+。生成单文件演示需要 Python 3。

```sh
npm ci
npm run dev
npm test
npm run build
```

predev/prebuild 自动从 lockfile 安装的 npm 包准备本地 OCR 资源，不依赖外部 CDN。

浏览器场景：

```sh
npx playwright install chromium
npm run test:e2e
```

当前云环境已安装 Chromium：`QINGBAO_BROWSER_PATH=/usr/bin/chromium npm run test:e2e`。测试使用公开虚构样票，并真正运行 OCR 引擎，不把写死文本当作识别结果。

## v0.6 体验打磨

新增旋转、四侧裁剪与恢复原图；调整图片后不覆盖已填字段，需重新识别核对。体验测试页可按角色进入任务并导出空白记录表，仍无真实用户测试结论。

## v0.7 事前费用申请

员工在“费用申请”创建计划，主管批准后预留预算。新建报销可关联同月、同类型的已批准申请，合计不超过其额度；支付后保留实际支出，结束申请释放未用余额。退回或撤回报销后，额度回到申请，不等于立即释放部门预算。部门预算仍为软预警。新备份包含申请，旧备份恢复时保留当前申请。

## v0.8 组织与审批树

右上角切换管理员，进入“组织架构”维护部门树和人员汇报树；进入“审批流程”配置报销/费用申请的金额与类型分支、顺序审批节点、财务人员，保存草稿、试算并发布。运行时按具体人员处理；新提交保留版本与路径，旧单据不被自动迁移。演示指南新增两条路线，完整规则见 [审批与组织设计](docs/审批与组织设计.md)。当前为树形表单编辑，不含拖拽、会签、任意嵌套或生产账号权限。

## v0.9 统一审批待办

审批中心集中展示当前具体人员可处理的报销、费用申请及付款登记；支持类型筛选、搜索、提交时间排序、路径进度与当前列表 CSV 导出。处理后同步更新角标；财务审核通过后保留付款任务。旧记录保留原角色流程，缺失提交时间时明确标注。演示指南、面试案例及功能迭代 Excel 同步维护。

## v0.10 图形组织与财务分工

组织架构升级为类似思维导图的节点画布，支持 CFO—部门总—员工、点选侧栏维护、快捷添加、缩放与折叠。新增总账复核（科目及核算归属）、独立付款岗位和付款工作台。管理员可将财务分工模板载入草稿并发布，已有组织和在途单据不被自动覆盖。详见 [图形组织与财务分工设计](docs/图形组织与财务分工设计.md)。

## v0.11 我的已处理记录

审批中心提供待办/已办双视图，按具体人员记录每次通过、退回和付款；保留处理时事项/金额、节点、角色、版本、时间及总账/付款摘要。支持筛选、搜索、排序、分页、筛选范围全量CSV导出及备份恢复。旧日志不猜测人员归属。详见 [已处理记录设计](docs/已处理记录设计.md)。

## v0.12 组织画布查找与定位

按姓名、岗位、部门或角色查找节点，点结果自动展开上级路径并定位；支持人员/部门范围、停用标记、路径导航和回到选中。补充未保存资料切页/切身份保护，不改组织或审批数据。详见 [组织查找与定位设计](docs/组织查找与定位设计.md)。


## v0.13：按日期回看已处理记录

审批中心 → 我已处理，支持起止日期（可只填一端）与今天、近7天、本月、上月、不限日期快捷选择。处理时间按当前浏览器本地时区划分日期，包含起止两天；近7天含今天，本月至今天。概览与页签保持本人全部处理次数，日期提示及页脚显示当前匹配次数，二者不混用。

日期与类型、结果、关键词共同筛选；改变日期回到第一页。CSV导出全部匹配页，并追加本地处理日期、筛选起止日期和时区，保留原始ISO处理时间。起止倒置时显示错误、禁用导出并标记结果未计算。清除筛选、切换身份/页面/待办页签或刷新会清空日期，不写入业务数据。

演示：赵航实际通过一笔报销 → 我已处理 → 今天，看到本人操作 → 改为上月观察空结果 → 填反起止日期观察错误 → 清除筛选恢复。没有真实历史日期时不要编造上月业务记录。生产权限、服务端统一业务时区、报销发生日期筛选和跨用户统计尚未实现。


## v0.14：员工报销进度总览

入口：选择员工角色及具体人员 → 报销进度（员工工作台也提供入口）。按流转中、待我完善、已登记付款分组；卡片显示申请金额、当前节点、当前待处理人、提交时流程版本和有序路径。搜索事项/单号/状态/节点/待处理人，每页10条；改变分组或搜索回到第一页，切身份/页面清空筛选。概览数字始终为本人全部报销，匹配数单独显示。

快照单据按申请人ID归属；无快照旧单/草稿仅在姓名唯一且部门匹配时归属。不按当前组织推测旧单审批人。当前具名路径来自提交快照，人员已停用/缺失或角色变化会提示核对，不自动改派。草稿/撤回/退回归入待我完善，退回显示最新可用说明，经查看详情可修改重新提交；重提后采用新快照。已付款不再显示待处理人，也不表示真实银行到账。

演示：林晓提交200元报销 → 报销进度查看赵航及后续周宁 → 赵航退回并注明补充用途 → 林晓在待我完善查看原因并修改提交 → 回到流转中。财务分工模板下叶禾的单据可依次显示沈岚、周宁、高璇和杜川。不要用演示身份选择宣称具备生产认证；当前没有催办消息、处理SLA、到账确认或事前申请进度总览。
